# Standalone controller runtime

Compile embedded scripts with `Resolver.resolve(parsed, registry)`. A `HostRegistry.Function` describes a qualified name, accepted argument and return types, documentation, capabilities, and a base work cost. A callback can charge extra work through its invocation context. The interpreter checks capabilities and argument types before the callback and validates the returned arity and types. Expected permission denials use the function's explicit error result when available. Contract violations and work exhaustion are runtime faults. Callbacks are trusted Java code and must be bounded and nonblocking.

`Simulation` compiles one interpreter per controller and owns a deterministic, sequential tick loop. Each controller gets at most one handler dispatch per tick. Controllers rotate in registration order when the tick cannot reserve the next handler's configured maximum work. Unused work is available to later controllers. At most 512 controllers, 256 subscriptions per controller and 256 queued handler deliveries per controller are supported. The configured queue may be smaller. Each queue also has a 262,144-unit logical payload cap, and source is limited to 262,144 UTF-16 units per simulated controller. Overflow drops the newest delivery and increments a counter. Already queued deliveries remain eligible. Errors are reported per tick, at most one per dispatched handler, without stopping other controllers.

Startup queues at registration. Shutdown stops intake, replaces pending work with shutdown deliveries, and stops timers. Timers use positive integer periods aligned to the simulation tick.
- **Emitting.** Java can emit qualified events with immutable scalar arguments (up to 16, matched against filters) and up to 16 values. A value may be a scalar or lists, tuples and dictionaries of scalars: at most 512 values, 8 levels and 16,384 characters.
- **Delivering to one handler.** `Controller.deliver(subscription, values)` queues an event for one chosen handler, which is how a host routes device events to `on gate.entityEnter(entity)`.
- **What a handler sees.** The binding `event` has `name`, `arguments` (a tuple), `payload` (the first value) and `values`. Declared handler parameters are bound to the values in order. Every delivery is copied, so handlers never share a mutable collection.
- **Subscriptions.** `Interpreter.Subscription` reports each handler's name, filters, source reference and parameter names. Filters are evaluated once during activation. Empty filters match any argument list, and nonempty filters match exactly in order. Newly emitted events can execute on a later tick. The scheduling owner can clear pending work, and `cancelCurrent()` requests cooperative cancellation.

The simulator supplies `log.info`, `redstone.read`, `redstone.set`, and `events.emit` with separate capabilities. Input changes from zero to a positive strength queue `redstone.rising` for the matching side. Changed output queues `redstone.changed`. These are simulated, host-defined APIs. The language and registry do not import Fabric or Minecraft.

## Debugging and diagnostics

Attach a `Debugger` to a controller with `Controller.debug(debugger)` between ticks. Without one, handlers run directly. With one, each handler runs as a coroutine of the scheduling thread and can pause at statement boundaries for a line breakpoint, a pause request or a step. Host callbacks and output still run on the scheduling thread. A paused controller is skipped, its timers do not accumulate, and `requestContinue` resumes it on its next turn under the same handler budget. `abortSuspended`, `shutdown`, detaching and `debug(null)` cancel a paused handler with a `CANCELLED` fault. `save()` refuses to snapshot while paused. `Pause` snapshots carry bounded frames and `ValueSummary` texts. `StatementLines` lists the lines that accept breakpoints. `Controller.statistics()` reports handler counts, faults and operations, and `ProgramConsole` is a bounded output history for hosts. See [ADR 0013](../decisions/0013-runtime-debugging.md).

## Named storage

`NamedStorage` is a bounded key-value store for program data hosts keep outside globals, such as a device drive's records. It stores detached copies of nil, Booleans, numbers, strings, lists, tuples and string-keyed dictionaries, nested at most 16 levels and without cycles. It holds at most 64 KiB in 256 keys. Every write is validated and encoded before anything changes. Failures carry `storage.key`, `storage.value`, `storage.full` or `storage.type`. `save()` and `load()` use a versioned binary format that rejects damaged input.
