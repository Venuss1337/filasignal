# FilaSignal Fabric mod

- `src/main` is common and server code; `src/client` is client-only (screens, editor, renderers). Server code must
  never load client classes, or dedicated servers crash.
- Programs: `computer/ServerComputers` is the one scheduler per server. Computers and drive-equipped devices are
  `ProgramHost`s. Activation is queued and bounded per tick; detaching happens on block-entity unload or removal.
- Hardware APIs: one `Spec` per kind in `peripheral/*Apis` and `HardwareHosts`; capabilities in `DeviceHosts`;
  native events and constants in `HardwareEvents`, routed by `EventHub`; device sampling in `DeviceObservers`.
- Network ownership, aliases and links: `NetworkDirectory` (persistent) and `NetworkPermission` (owner, trusted,
  admin). Client requests: `EditorNetwork` and `DeviceConfigNetwork`, validated, rate-limited and distance-checked.
- Drives: `drive/DriveStore` holds records in saved data and a mount table so one drive identity runs once.
- After changing host APIs, events or constants, regenerate the API catalog
  (`FILASIGNAL_UPDATE_DOCS=1 ./gradlew :filasignal-fabric:runGameTest`); `DocumentationGameTests` fails when it is stale.
- New GameTest classes must be listed in `src/gametest/resources/fabric.mod.json`. Tests share one world and run
  concurrently: place far from other tests, never assume global state (for example all drive records) is yours.
- Textures, models and blockstates are generated by `tools/assets/generate.py`; recipes by `tools/recipes.py`.
