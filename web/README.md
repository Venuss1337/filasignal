# FilaSignal documentation site

The public documentation for FilaScript (the language) and FilaSignal (the Minecraft mod), built with
[Astro](https://astro.build/) and [Starlight](https://starlight.astro.build/). It is published as a GitHub Pages project
site at `https://venuss1337.github.io/filasignal/`. Building the mod never needs this folder, Node.js or Bun.

## Develop

Install [Bun](https://bun.sh/) 1.4 or newer, then from this folder:

```sh
bun install --frozen-lockfile
bun --bun run dev      # http://localhost:4321/filasignal/
bun --bun run build    # builds dist/ and runs scripts/check-site.ts
bun --bun run preview
```

`--bun` runs Astro on Bun's runtime. Astro 7 also runs on Node.js 22.23.4 or newer.

## Layout

| Path | Contents |
| --- | --- |
| `src/content/docs/language/` | FilaScript: getting started, the language guide and the reference. |
| `src/content/docs/minecraft/` | FilaSignal: getting started, guides, hardware, tutorials and the API reference. |
| `src/components/` | Components that render reference material from data: API entries, events, constants, recipes. |
| `src/data/generated/minecraft-api.json` | The Minecraft API catalog, **generated** from the mod's host registries. Do not edit. |
| `src/data/recipe-tiers.json` | Recipe progression tiers, generated by `tools/recipes.py`. |
| `src/grammars/fsig.tmLanguage.json` | FilaScript syntax highlighting. |
| `public/renders/` | Asset renders of block models from `tools/assets/preview.py` (not screenshots). |
| `public/screenshots/` | In-game screenshots taken by the mod's client GameTest (`HardwareShowcaseTest`). |
| `scripts/check-site.ts` | Post-build checks: links, anchors, base path, search index, required pages, placeholder text. |

Recipes are read from `filasignal-fabric/src/main/resources/data/filasignal/recipe/` and example programs from
`examples/` at build time, so the site never keeps a second copy.

## Keeping it correct

- **Language examples.** Every `fsig` block under `language/` is parsed, checked and run by
  `filascript-core`'s `DocumentationExamplesTest`. A following `text title="Output"` block must match the printed
  output. Mark a fragment with `check="none"`, intentionally broken code with `check="invalid"` and a deliberate
  runtime fault with `check="fault"`.
- **Minecraft examples.** Every `fsig` block under `minecraft/` is resolved against the real host registry by the
  `DocumentationGameTests` server GameTest. Blocks run on the computer unless they name a device kind, such as
  ```` ```fsig target="entity_detector" ````.
- **API catalog.** The same GameTest fails when `minecraft-api.json` is stale. Regenerate it with
  `FILASIGNAL_UPDATE_DOCS=1 ./gradlew :filasignal-fabric:runGameTest` and commit the result.
- Root-relative Markdown links such as `[editor](/minecraft/guides/editor/)` get the `/filasignal` base added at
  build time. In components, use `withBase('/path/')` from `src/lib/site.ts`.

## Deploy

`.github/workflows/docs.yml` builds and checks the site on pull requests and deploys `main` to GitHub Pages. The
repository's Pages source must be set to **GitHub Actions**.
